# Snapshot boundary

The container library in `server/snap` implements S10. It receives bytes, headers and filesystem paths, never reaction, permission or physics tables. Its object-section codec is the single exception for complete `Objects` access. Other table owners provide their own section functions, taking individual authoritative tables. Derived indexes are rebuilt after reading and are not serialized.

The alternatives were a universal snapshot context containing every table, separate temporary buffers per section, and one bitsery output passed sequentially through section encoders. The first breaks the ownership boundary; the second adds a full copy and allocation to the step pause. The third is used. `begin`, `section` and `finish` write into an acquired reusable byte buffer. A section callback lives only during that call and receives the output serializer. All thirteen S10 tags are present in their specified order, even for an empty capture. TEXT additionally contains authoritative catalog/model identities and parameter references. SCST includes last watch answers (including consumer-specific allocations), PROP includes process revisions, QUEU includes typed event payloads, and SHRD includes allocation meters.

The output adapter uses little-endian bitsery encoding. Header strings and table vectors use bitsery's length encoding. Section lengths and the footer are fixed u64. The footer is standard xxh64 with seed zero over all preceding bytes. Parsing verifies the footer, exact format, runtime allowlist, section boundaries and order before exposing borrowed payload spans. Each owner then checks that its section decoder consumed its entire payload. Invalid local snapshots are explicit errors; they are never partially restored into a running world.

The writer owns only pending completed buffers, compression state, its directory and retention settings. A two-buffer pool lets the step reuse storage without touching a buffer being compressed. If both are occupied the step postpones snapshot work and records it; it never blocks on compression. The worker compresses at configured zstd level, writes `snap-STEP.amb.zst.tmp`, renames to the final name, prunes its own completed snapshots, and returns the source buffer to the pool. `finish` joins and surfaces I/O failure. Capture writing uses the same file container and section encoders, with a selected set of handles and incident rows rather than a separate invented fixture format.

Tests check exact independent header/footer parsing, corruption/truncation/runtime refusal, sparse reconstruction and slot-generation reuse, asynchronously written zstd round trips, retention, and restart continuity once every owner codec is present. Benchmarks distinguish the step's encode pause, off-thread compression and complete restore; a small codec fixture cannot establish the full-world performance gate.

## Owner assembly and restore contract

Composition supplies thirteen short-lived section callbacks in `snap::tags` order. `snap::encode(Buffer&, Header, SectionWriters)` writes each callback directly into one reusable buffer; `snap::decode(View, SectionReaders)` gives each reader a bounded payload and checks complete consumption after that section's final owner call. These callback arrays contain only functions over bytes. Each composition closure captures the exact tables of its own section by reference; no closure captures a world, main object, shared service context or another array of adapters. Decoding targets a fresh process's tables before its step loop starts. An error discards that fresh runtime rather than partially replacing a running world.

The following subpayload order is part of format 1. Per-section helpers in `server/bindings/checkpoint` expose these exact arguments; none retains references after returning. OBJS continues using the privileged existing object serializer directly.

| Tag | Ordered owner calls and authoritative contents |
| --- | --- |
| OBJS | `snap::write_objects` / `read_objects`: original slot/generation and all object columns, preserving identity in captures. |
| PROP | `react::write_properties` then `write_settings`: properties/processes including revisions; instance/model/plot/world settings. Baked measurements and runtime lux are derived, not copied into this section. |
| RELS | Authored relations; space physical relations; lifecycle named parts. The derived declared-parts relation is rebuilt from named parts. |
| SHRD | Shared totals/contribution parts, gives-to, allocation answers and allocation meters. |
| TEXT | Catalog models; parameter blocks; scripts; model/instance text; authored details/refusals. IDs/high-water marks survive selection. Immutable geometry/source/script artifacts remain in the asset store. |
| PLYR | Permission players, player wallet balances, plots, groups; control profiles. Profiles contain hashed authentication references, never key plaintext. |
| GRNT | Grants, offers, trades, sparse inherited owner limits. |
| SCST | Flat script state and last-delivered subscription answers/revisions; explicit instance-script installations. WatchLinks and Triggers are rebuilt. |
| TIMR | Timer wheel time and copied timers, including threshold tokens and causal Origin. |
| QUEU | Foreground/background work, intents and next-record ID; copied drive input rows/high-water mark. Session sockets and callback pointers are absent. |
| REQS | Requests; gap counts; last gaps; capture references; copied pending fixture descriptors. |
| RAND | Per-object random state. |
| MOVE | Dynamic/body linear/angular velocity and sleeping state copied from space. |

Registry terms, materials, bindings and immutable rule history are loaded from the header's exact registry hash. Script/model rows are restored before loading rules that refer to their IDs. Script source/runtime/registry pins are checked by the existing immutable artifact loaders; no caller-supplied declaration substitutes for the validated artifact. Runtime-version compatibility is checked before any owner reader runs.

Restore proceeds in this order:

1. Parse and validate the entire container, read the pinned registry document, and load its terms/material definitions. Decode authoritative sections into fresh plain tables. Each owner rebuilds its own sparse positions/reverse indexes while reading. The composition sets clock step and journal next ID from the saved values.
2. Resolve model/parameter artifact hashes and rebuild asset measurements/settings projections; load the pinned scripts into a fresh region VM at this offline boundary, applying authorized registry activation. Load registry rule history only after script identities exist. Rebuild model/instance/rule trigger projections.
3. Build a fresh space from actual collision assets and restored bindings/poses; restore declared assembly structure, attachment mirrors, moving-body velocities and sleep state. Rebuild navigation from geometry and resume each saved movement goal/speed/origin as an intent, without replaying a chosen action.
4. Rebuild source projections and current computed measurements, including subscribed illuminance, from the restored runtime. Rebuild WatchLinks in `SyncMode::Restore`: retain saved last answers, watch revisions and timers, create no replay and no new late-rule catch-up. Existing background work resumes from QUEU.
5. Requeue saved fixture/bake jobs from immutable descriptors through their actual workers. Live transport sessions do not survive a restart; pending rows may finish their world operation but a missing socket cannot stall the simulation. The integration adapter explicitly decides how to notify a reconnected player. Begin the same normal phase loop used for a new world and fixture subprocess.

`Space`, navigation tiles, Jolt body IDs, visibility caches, replication baselines, observer last-observation caches and VM heap objects are derived runtime state. No decoder claims to restore them by merely reading MOVE or scalar state. The actual rebuild and its errors are observable to the caller. A fixture subprocess uses this same restore path and full runner, then changes only its declared givens and candidate-rule activation.

## Capture filtering

A capture invokes the same thirteen encoders and decoders; a selection parameter changes rows, never their payload schema. Missing selection means a full snapshot; an explicitly empty handle span means an empty capture. The S12 seed is target plus requester's actual last-observed handles (both full and short observations) and the acting body, or the measured-radius set for a mid-chain gap. Add objects one relation edge from those seeds using the current authored/physical/declared-part relation views; this is the design's local neighborhood, not an unbounded graph traversal. Resolve named assembly descendants and custody parents required to keep selected assemblies coherent. Object generations remain original; unrelated slots are inactive.

Priority sharing adds one necessary mechanical dependency edge: active demand contributors of initially selected shared subjects must be present, so their ordinary instance/model/plot/world priority settings remain exact after a local mutation. Add their required assembly/custody closure, without recursively expanding their relations or following their other shared subjects. Equal sharing needs no external priority evidence. This may enlarge a capture beyond its spatial neighborhood and must remain visible in capture metadata.

Per-owner filters retain only selected object rows, their incident bookkeeping and relevant global definitions. Preserve a selected shared row's exact total and contribution parts even when a contributor lies outside the neighborhood: deleting that part would change the captured answer. Off-neighborhood handles in retained scalar values or contribution provenance remain ordinary invalid handles in that capture, never phantom live objects. Prune outgoing/incoming relation endpoints and subscriptions whose installed consumers lie outside the final object set; retain saved answer data only for installed selected consumers. Preserve only selected receivers' timers, work and movement intents; keep typed handle arguments as data. A queued InputWork survives only with its matching selected copied input descriptor. Captures do not launch prior pending external authoring or fixture jobs.

Catalog selection closes over each selected binding's model, parameter block, variant/default child models, default and explicit scripts, and all rule script definitions referenced by the pinned registry history (including retired/disabled versions required by its loader). It includes corresponding metadata/text, not unrelated submissions. World settings and registry definitions are small shared semantics and remain available; model/plot settings are restricted to referenced model/plot IDs.

Permission selection retains relevant players (actor, selected owners/controllers and retained grant/offer participants), referenced groups/plots, their player wallets. Inventory/mailbox lists contain only captured goods. Keep grants relevant to those selected holders and object/plot/account scopes plus their delegation parents; keep offers only when their goods and complete assembly are selected, and trades only when both sides' retained offers are present. Preserve ID vector high-water marks with inert gaps so existing references do not change identity. This is local fixture authority, not a transfer to the original live world.

Tests must encode all thirteen nonempty sections, restore a fresh runtime, and compare continuation with the original: process/threshold crossing, explicit followed watch, actual Luau state/RNG, queued Origin, movement, inventory/grants/trade, catalog parameter topology and request history. Captures must prove an unrelated object, its script state, timers, work, wallet balance and text are absent while selected facts and incident authority remain usable. Real space/navigation rebuilding and full fixture runner continuity are separate integration gates and may not be reported passed by a codec-only round trip.
