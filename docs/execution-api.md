# Handler execution and completed records

`bindings/execution` runs one already-selected Luau handler and finalizes its records. The execution context contains only the VM, script-state rows, per-object RNG rows, identity and the declared-part relation. The loaded VM's individual bindings hold their own narrow operation contexts. Execution receives no ledger, physics, catalog, sockets, construction tables or universal service object.

An invocation input is copied data: receiver, sender, trigger/payload, logical step/rate, causal Origin, acquired read handles and optional immediate-action metadata. An authenticated body action alone supplies a bounded `direct_body` envelope. `action_caller` is descriptive immediate input identity, supplied for direct or script action handlers; events, watches and timers omit it. It is never an inherited player grant. Finance and future scheduled script actions always act as the installed script holder.

Execution resolves the declared descendant closure, adds typed payload handles to read acquisition, binds the receiver's scalar state and deterministic RNG row, and calls the real VM. Returned effects remain copied drafts. State/process/payment writes made during the call are already live. A handler error keeps those completed effects. Missing/disabled handlers return missing; there is no synchronous self.act reentry.

After each return, composition applies its typed structural requests through the separate lifecycle/construction adapters and folds the actual structural result into `effects.changed`. No unresolved structural request may be published. This happens before the next handler reads the world. Structural creation/destruction record drafts are buffered separately from emitted work, so the final action outcome is known first.

For an action, composition holds only the completed invocation drafts until all applicable handlers finish. It appends the action record, then each completed handler record, then that handler's completed structural/log drafts and emitted descendants stamped with its Origin. The foreground queue drains those descendants before the next external input. For an event/watch/background item, the same finalizer directly uses the incoming Origin. There is no state rollback, copied world or history traversal.

The finalizer takes only Journal/queues/timer wheel and completed values. It does not retain execution context or module tables. Its return contains the actual handler count, changed flag and diagnostics for a transport adapter to render. An alternative was writing records before running Lua, which cannot report actual effects; another was logging the handler first and reconstructing its parent later. Completed drafts preserve both truthful outcomes and forward causal order.

Tests use actual Luau to verify broad-to-narrow writes remain live, direct-body versus event authority, script-generated actions remain queued, partial error effects, inactive scripts, per-object state/RNG continuity and action/handler/descendant record order. Metadata tests alone do not establish a playable world; the main runner must still apply structural outputs and actual physical input phases.
