# Native observation and spectator queries

`bindings/viewing` adapts authenticated control DTOs to existing read/query modules. It owns no world tables and executes no gameplay. Each registered operation has its own context and callback; there is no shared world/service context.

`SessionViews` contains session-local sent observation caches, pending full observation DTOs, last-observation handles (including short rows), acquired read handles, authenticated player/body and current view position. Reconnect/replacement creates a fresh cache; close erases it. `refresh_view` can prepare a pending scan when `observe::ActiveViews` is dirty without advancing the sent cache. `look` advances that cache only after returning a response. The root owns when dirty perception runs and when the normal turn queue admits a query. Handles never become mutation authority by appearing in this cache.

Look resolves the body's actual effective asset observer binding, rigid pose and dim threshold, then uses `observe::scan` against Space with declared-part, held-object, light and zone data. Descriptions use actual catalog measurements and live value reads; `says` remains attributed maker text. A larger requested limit rescans. Incomplete spatial work is explicitly reported. The result retains the implemented S5 structured observation envelope and omits unchanged records/action menus through the existing observation formatter.

LOOK's property projection follows Technicals §7 and S5.3's measured-object summary. It retains present intrinsic, measured, state and shared answers. A setting is included when explicitly authored at instance/model/plot scope, listed in the effective asset's replicated terms, or referenced by its bindings. Thus a new authored quantity or setting works without a name whitelist, while unrelated world-only defaults are not repeated on every visible object. Binding string references resolve through the actual term registry; numeric `term` fields are explicit IDs, and ordinary numeric scalar binding values remain constants. There are no default state/shared values: those sources are included only when the actual reader finds stored state/process/shared incidence. INSPECT continues to read every requested registered quantity/flag, including inherited world settings.

Alternatives considered: replicated-only LOOK would hide useful measured/material properties; adding a separate author-written perception declaration would expand the content contract unnecessarily. The selected projection uses existing authored specificity and immutable asset declarations, without new authority or persisted fields.

Full object rows and current inspection include a separate public `elaborated` array: `{id,elaborated:true,text,author:"p:N",created_s}`. Everyone sees the same authored detail beside maker claims, without changing measured properties. Refusal statuses are not included in this public detail array. Detail edits participate in observation comparison, so an invalidated short row becomes a full row even within the same step. `CatalogRead` appends a required readonly `AuthoredTexts` reference after `inspection_terms`; `ObjectDescription` appends a defaulted presentation array after `actions`.

The separate inspect context reads current generations, effective variant, quantities, relations, ownership/presets and current permission decisions. A valid handle can be inspected without an invented Use requirement; action rights still gate mutations. Special targets are self, inventory, grants and plot (current land). `plots` returns only the caller's owned plot descriptors, including actual 2D bounds; `plot:N` reads a public land descriptor by actual positive plot ID. These reads add no Build/Enter/Transfer authority. Model/script inspection reads immutable verified public source caches supplied during catalog import, never arbitrary files on the writer. Full and short observation handles both remain available to the root's ordinary capture adapter.

As an explicit prototype implementation choice, an object's current owner or a player with current Edit also receives its generic `script_states`. This is a read of actual stored state, without stock/resource names or interpretation. Each row is `{script:"s:N",state:[{key:123,type:"number",value:19},...]}`; keys remain integers or strings and types distinguish numbers, booleans, strings and tagged full handles. The state list covers actual default/explicit installations plus currently applicable approved world rules. A disabled/unmatched rule's retained state is not presented as an active installation. Other viewers still receive public code/properties/measurements, without private flat state. `InspectBinding` therefore appends readonly ScriptStates and RuleVersions references after events_per_response. This inspection grants no mutation rights.

Action discovery reads only native declarations, registered signatures and actual model/instance declarations. Model actions within reach and body actions are listed regardless of whether a later action's right will be granted. Detail includes registered typed inputs, dimensions, declared checked right/reach and an example. Unknown terms/targets and stale generations return structured bad_input/stale results rather than an invented affordance.

Hearing is the actual `observe::Hearing` queue produced by sound bindings. Tool responses consume only that session's pending sounds, preserving oldest-first order among the newest requested count and explicit omitted count. The gateway continues to merge pushed non-sound events. No observer receives a synthetic speech generated by a keyword policy.

A view-interest sink is a function pointer plus operation-local context containing only transport/replication registrations. Root uses it to update both interest projections and initial metadata/keyframes. The viewer's free camera uses the same sink without creating a player body or world action. Existing `presentation` helpers produce catalog/model/material/term/object metadata; parameter variants keep their own effective manifest bindings.

`RecordFeed` retains a bounded copy of completed S7 JSON plus positions sampled at publication. It is a spectator cache; the full authoritative record remains with the record writer. `events` accepts the existing since/limit/root/thing fields. Ordinary sessions receive only their own/body-near records; an authenticated debug mode or explicit architect role may request the global trace. Missing older cache rows and omitted matches are reported. A root filter never silently grants broader record access.

Optional `detail:false` selects a causal summary projection after the same filters, privacy checks and tail selection. It omits only the heavyweight `observation`, `measured`, `source`, `bytecode` and `manifest` fields. IDs, attribution, things, cause/root, result, errors and action arguments remain. The default is the original full record. The browser's periodic recent feed uses summaries, while explicit causal-chain expansion requests full records. No stored S7 record changes.

Debug has its own Space/identity/clock context and an optional narrow metrics callback. It returns actual collision/navigation/path/volume lines from `space::debug_lines`, or actual counters. It does not fabricate navigation triangles from model meshes. Query permission remains the registered control mode/role policy.

Tests must use actual Space and current value/VM bindings for full→short updates, held/far visibility, hearing distances, live changes after an earlier observation, stale generation rejection and trace filtering. Pure DTO fixtures establish formatting only; the integrated browser/server gate remains separate.
