# Native authoring adapter

`bindings/authoring` bridges the three authenticated authoring controls in [gateway-api.md](gateway-api.md) to the immutable catalog and the simulation writer. It owns no sessions, accepted-input store, world tables, gameplay dispatch, or approval policy.

The composition validates the control envelope and retains the accepted `drive::Input`. It retains `SubmissionQueue{worker,terms,registry}` alongside the worker; `register_inputs(operations, queue)` installs the private model, variant and script submission callback. Model decoding resolves the supplied material against the current registry and accepts only string name/description/writing fields. Canonical parameter JSON must be an object. Asset/source identity and numeric parameter bounds are verified against the published artifact in the worker. The transported `manifest` is never used as authority. Immediate decoding failures retain the existing input rejection path; they do not enter the background queue.

`Worker(WorkerSettings{asset_root,pins,limits})` starts one FIFO background thread. `submit(input_id, request, RegistrySnapshot{terms,pin})` copies all required data; it never retains registry or player/world references. Model work loads the actual source, exact canonical parameter bytes, bake manifest and all declared child artifacts through `catalog::read_asset`, verifies runtime pins, and resolves manifest terms. Script work calls the real fresh-VM catalog validator with the copied registry and configured declaration limits. Results from `poll()` are `Completion{input_id, PreparedModel | PreparedVariant | PreparedScript | Failure}` in submission order. Shutdown discards queued work and joins the one bounded current validation. No unsandboxed Python executes in this adapter: Python CAD ran in the separately configured bake supervisor before registration.

The simulation writer looks up the original accepted input and calls `complete_authoring(input, completion, session_live, catalog, scripts, journal, step, hz, seed_authors)`. That operation installs the result with its authenticated author/time, or records a denied unchanged attempt if the session has closed or validation failed. It appends exactly one native completion record with the original Origin and returns its actual `record_id`, reply and added model IDs. Duplicate variant registration is NoEffect and retains the source model's actual author/time credit. Main only publishes the returned definitions and delivers the reply through the original sequence. Results whose accepted input no longer exists are discarded. Read-only controls remain independent of this authoring wait under the existing session scheduler.

`CatalogInstall` groups Assets, Models, ParameterBlocks, ModelTexts, ModelSettings, AssetMeasurements, PublicSources, read-only Scripts/Terms, configured measurement term IDs and the geometry-only hook. Both model and variant installation use this one capability context. `install_model(prepared, author, created_s, catalog)` imports verified immutable assets, optionally invokes `GeometryHook::prepare(local, actual_asset)` before exposing a model, creates a distinct model identity, and projects actual volume/capacity for the root and ordinary declared child models. Batched variants are validated through existing catalog functions on fresh proposal-only scratch tables before any live family IDs are exposed. The root supplies a hook retaining only geometry cache/Space loading references. Geometry cache reuse never merges authorship or model identity. Reply: `{ok:true,model:"m:N",hash,measured:actual_manifest,variants:[...]}`.

`install_script(prepared, author, created_s, ScriptInstall&)` checks collisions with the actual reserved native player actions, persists the compiled/source/declaration artifact, loads it into the existing VM, imports its distinct script identity, and caches its public source. Its context contains only Scripts, VM, PublicSources, read-only NativeActions and configured script artifact root. World rules are always imported unapproved and inactive; no uploaded fixture, declaration field, or model identity can bypass the separate elaboration approval workflow. Reply: `{ok:true,script:"s:N",hash}`. All installer failures use `{ok:false,errors:[message]}`. The existing control layer supplies `t:"result"` and the original request `id`.

The composition publishes catalog/presentation metadata after successful installation using the existing presentation adapter. Source caches contain actual verified CAD/Luau and no credential or private source path. Session/profile credentials remain exclusively in the control module.

An alternative would run validation synchronously in a control callback. That is smaller but blocks the simulation on disk access and compilation. A separate external daemon adds a second correlation and deployment boundary without improving the already immutable catalog worker contract. One local background worker is the prototype's chosen balance.
