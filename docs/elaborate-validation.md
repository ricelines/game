# Elaboration evidence

`amber_elaborate` implements S12 request/claim/answer/refuse records, persistent last-gap/capture references and counters, selected REQS codecs, asynchronous S10 capture compression/publication and a real subprocess fixture-job transport. `catalog::AuthoredTexts` stores detail/refusal text with separate author/time/target attribution and selected snapshot support; maker text remains in its existing tables.

The optimized warning-as-error and Address/UndefinedBehavior Sanitizer suites pass the elaboration lifecycle, acceptance and transport tests. Assertions cover the exact first-three automatic captures, player historical capture reuse, explicit-before-gap listing, role/claim checks, with/without comparison criteria, vacuous/error rejection, failed-job session release and request retry, attributed text, full-handle/Origin persistence and selected-object filtering. The fixture grammar accepts numeric/boolean state and `{handle:'subjectName'}` state/equals, with action payloads kept separate from property values.

The subprocess test genuinely launches another executable, checks timeout termination, concurrent progress, bounded diagnostics, malformed or mismatched report rejection and missing-executable `unavailable`. Its child is explicitly named `fixture_transport_probe`. It does not load a game world and is **not** evidence that rule fixtures pass. The capture I/O test writes and reloads an actual S10 container through zstd, but does not claim full selected-world restoration.

The actual approval gate is wired as `amb fixture CAPTURE --job JOB.json --result RESULT.json`, using the same world restoration, action dispatcher, VM, physics and step code as normal play. [The retained live S12 regression](live-elaboration-validation.md) uses real candidate/baseline children, rejects a vacuous rule and activates/retries a useful rule only after the paired result. The transport probe remains transport-only evidence and cannot approve a candidate. A final-binary rerun is tracked separately in that live report.

`elaborate_bench` measures existing-pair gap updates at 16–29 ns, sorting a page from 10,000 requests at about 1.6 ms (including only the returned page's text copies), and hashing/enqueueing 100 KB of completed capture bytes at about 0.9–1.0 ms. Compression/file publication takes about 1.1–1.4 ms off-step in that run. These separate encode/hash/I/O costs; full-world snapshot and fixture duration remain integration measurements.
