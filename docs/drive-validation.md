# Driver validation

At the isolated driver checkpoint, the optimized build with `-Wall -Wextra -Wpedantic -Werror` and the Address/UndefinedBehavior Sanitizer build passed all 23 tests (0.81 and 6.07 seconds respectively). These include actual structural operations, threshold turns, VM handle acquisition, snapshot filtering and pre-publication selector synchronization. The architecture checker passes.

The driver tests execute real compiled Luau. They verify that an action's emitted event completes before the next external action; a body invocation stays installed on its body and only the resolved declaration receives physical authority; scripts cannot borrow a player's body; selector flags are resolved from current authored values; explicit unchanged watches remain modeled while bare quantity handlers leave shared gaps; and term names, numeric IDs and typed references reach Luau as the same term ID. Separate checks cover actual post-handler lifecycle allocation before action/handler/create publication, native operation validation, deferred input identity/provenance round trips, nearest-bound reach, the latest-twenty-phase average, overrun behavior and minimum background progress.

`drive_bench` performs 100,000 event plans and actual Luau invocations, checking the final persistent state counter. The optimized run measured 2.39 microseconds per invocation, approximately 419,000 invocations/second on the shared development host. This includes dispatch, invocation setup and persistent state mutation; it does not include a full world's geometry, network, logging or snapshot phases and establishes no integrated 20 Hz claim.

`server/main.cpp` now supplies the operation-local adapters and configured limits, permission/reach checks, selector/allocation reconciliation, rebound watch/timer consumption and the remaining S2 phases. Specialized wallet, land and role operations perform their own native preflights; registration alone grants no authority. The timings above remain module-only. Actual composition evidence is recorded separately in [live elaboration](live-elaboration-validation.md), [recovery](live-restart-validation.md), [spatial play](live-spatial-validation.md) and [resident/browser validation](resident-validation.md); their final-binary refresh is tracked there.
