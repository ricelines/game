# Live elaboration inputs

`bindings/elaboration` adapts S12 through ordinary reserved native actions. It owns no world and reads no physics, VM, ledger or live script state. Each request/list/claim, rule submission, patch-note, detail/refusal and completion operation receives its exact tables. A small answer dispatcher carries only three native operation entries; each answer kind has its own context.

`engine.request_model{note}` copies the player's actual retained last gap. `engine.requests{page?,page_size?}` uses the existing explicit-first/gap-count ordering and permits a caller-selected positive page size. `engine.claim{request}` claims an open request. `engine.answer{request,kind,...}` takes kind `rule` with `script` and optional named `subjects`, `patch` with a note documenting already authorized changes, or `detail` with authored text. `engine.refuse{request,text}` records attributed refusal text. IDs are `request:N` and `s:N`. There is no caller-supplied test list.

A rule answer copies only the catalog script's verified immutable tests, artifact, registry pin and runtime. Named subjects always include the historical target and original requester's body when present. Optional aliases carry full handles; the actual fixture child validates that those identities exist in the capture. The handler submits the copied FixtureJob off-step, with explicit configured timeout/report bounds and worker concurrency.

The issuing input's plain `{input,session,sequence,request}` order flows through controls → turns → NativeCall. NativeCompletion and ActionOutcome return a deferred marker. The completed chosen action's Origin flows through InputReply into the existing parked Input.origin, so no hidden current-session state or extra response map is required. That session's mutation lane remains pending; other sessions, read queries and world steps continue. Script-generated actions never receive direct input order.

Completion runs on the writer. It matches the pending job and parked input by actual session/sequence, rechecks the actor's current role, claim, immutable artifact/tests and with/without acceptance, then invokes the narrow RuleActivation callback. It closes the request only after activation succeeds and completes the exact original input once. Failure discards the pending job while leaving the request/claim open. The returned effects use the stored chosen-action Origin; the returned notification goes to the original requester. A disconnected transport does not grant or revoke world authority.

`engine.rule_activation{script,active}` controls already approved immutable rule versions under elaborator/architect registry authority. Enabling an old approved script restores it by the ordinary append-history operation; disabling affects its current entries without reviving predecessors. An untested script cannot be enabled. Only successful fixture completion supplies RuleUpdate::Validated. Composition's exact callback updates cached VM approval/activation, current triggers/watches, retired consumers/background versions, one-time catch-up and the immutable registry pin/record.

The alternative of replying `fixture_pending` immediately would release session order before the accepted edit finishes. Waiting synchronously would stall the world. The deferred copied-input path reuses the existing asynchronous authoring mechanism and keeps the fixture process separate from live tables.


Validation: `elaboration_bindings_test` exercises real request/claim/detail handlers, independently attributed text, verified test copying, exact original target/requester body, the subprocess transport interface, role/claim/candidate rechecks, vacuous baseline rejection, exactly-once completion and explicit enable/disable authority. Its executable is a transport probe; it does not claim gameplay fixture acceptance. Actual candidate/baseline gameplay is the shared server runner owned by composition. `rule_activation_test` separately executes actual Luau for late first contributions, indexed explicit and implicit along watches, two-hop fallback, late catch-up, supersession/timer invalidation and preservation of another script's pending answer. Both pass optimized and Address/UndefinedBehavior sanitizers.

Optimized benchmark (10,000 contribution → indexed relation/watch resolution → real Luau state/result writes): 6.76 µs/op with zero unrelated objects, 5.31 µs/op with 100,000 unrelated objects. Timing includes actual state and authoritative property mutation; source compilation and Journal I/O are excluded. The second run benefits from warm caches, so these numbers demonstrate the measured workload rather than a precise speedup.
