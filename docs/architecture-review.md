## Lifecycle coordination review

The current implementation addresses a separate maintenance problem exposed by
review of the preceding composition file: creation, replacement, retirement,
startup and visibility changes required overlapping caller-built callback lists.
Those lists and their shared pending-retirement sink are removed. The fixed
`ObjectLifecycle` operations coordinate owner cleanup while handles remain valid;
`SceneProjection` coordinates visible registration, movement, fact changes and
illumination sampling. Their retained owners are private, and engine APIs and
Lua bindings continue receiving only their own projections. See the complete
[scene contract](scene-api.md).

The runner still owns S2 sequencing. It now calls named scene operations rather
than reproducing separate light/zone/replica/illuminance registration and cleanup
at every lifecycle entry point. Hidden rebind/restore has an explicit visible
subset, so updating measured inventory mass does not create ghost lights, zones
or replicas. Resource settlement remains before cleanup; declared rows are
released after every owner has finished. Genuine births receive start events,
while retained edits and restore preserve saved script state and watch answers.

The integration sources now share one `amber_bindings` library. Independent
engine owners remain separate; execution retains its separate library because
`drive` consumes it without an integration dependency. No compatibility aliases
keep the removed per-operation targets alive. Editing uses four responsibility
contexts and direct typed metadata/publication references; the single mass
reconciliation path is a typed optional owner rather than a callback list.

The initial [nine-test focused checkpoint](../reports/lifecycle-focused-refactor-2026-11-15.json)
uses actual Lua/Jolt and live derived tables, including hidden rebinding,
visibility restoration, lifecycle cleanup, measured/foreign-followed watches,
terminal light/ambient sampling, and ordinary commerce custody. Its binary
predates only the final metadata/publication reference cleanup. The coherent
Release, live-server and [refreshed sanitizer checkpoints](../reports/native-sanitizer-refactor-2026-11-15.json)
below validate that cleanup. Earlier report hashes remain historical evidence.

## Required outcome

A playable world must let agents author geometry and behavior, use one another's creations, encounter and fill gaps, trade and delegate rights, while people watch the authoritative world. The café is a workload authored through those facilities. It is not an engine feature. A handful of scripted demonstrations cannot satisfy the prototype goal.

The native engine supplies geometry, physics, navigation, scheduling, generic term evaluation, authority, atomic exchanges and observation. The laws above basic physics live in registry content and Luau. Starting content uses the same submission, installation and rule activation paths available during play. A bootstrap file may supply initial identities, plots, assets and accounts; it must not enable privileged scenario logic.

## Table-level boundaries

Use small C++ libraries with narrow public APIs, plain mutable tables and direct calls. Related operations may have separate public headers without sharing a universal context. The executable owns table lifetimes and sequences functions. It contains no gameplay handlers and passes no executable, server, world or store object into a module. Replacing `Core&` with `Services&`, a tuple of every table, a global singleton or a captured lambda with the same access fails the boundary.

The following is an ownership matrix, not permission to give a module every table in its row at every call. Each public function lists the exact references it needs; unrelated table references must be absent. Read-only references remain `const`. Initialization and restoration populate tables before stepping; ordinary runtime mutations follow these writers.

| Module | Runtime writes | Permitted reads and outputs |
|---|---|---|
| `store` | Object allocation, generation/free slots and structural row lifecycle; sparse-column storage | Table primitives only. Receives explicit initial row fields. No dispatch, spatial queries, authority, content or transport. Owners of affected tables remove their rows when an object is destroyed. |
| `step` | Step counter, input/work queues, timer wheel, dirty-watch bookkeeping, intent lifecycle | Due times, narrow intent/status fields and phase costs. Calls module entry points with their named table arguments; does not implement actions or reactions. |
| `react/registry` | Terms, material definitions, rule versions and trigger indexes through authorized edits | Structural declarations and selectors. No maker's text, object-name matching, scene coordinates or engine dependencies. |
| `react/runtime` | State properties/processes, shared contributions and `gives_to`, authored relations, watches, script state and random state | Live object identity/model/material, declarations and effective numeric values needed by a handler. Emits work, records and narrow primitive requests. Cannot mutate ownership, money, arbitrary transforms or another object's state. |
| `space` | Transforms from placement/movement commands and simulation; `contains`, `supports`, `attached_to`, `in_zone`; spatial indexes and derived Jolt/Detour data | Geometry manifests, object flags, explicit collision/visibility/render-independent material values, relevant intents. Produces contacts, query results and navigation diagnostics. No power, oxygen, charge, rent or institution tables. |
| `perm` | Ownership, group/preset fields, players' groups/grants/inventory/mailbox, grant lookup, offers, confirmations and balances | Object identity/plot/parent/flags and narrow trade item metadata; current step. Requests structural parent/escrow changes through the lifecycle/movement helpers. No reaction, spatial simulation or content-specific pricing. |
| `perception` | Per-session observation bookkeeping and invalidation state only | Narrow object/model/material/value views, maker's text, declared actions, query results and the observing player's public/session fields. Calls separate permission-description functions for inspect. Cannot change world state while deciding visibility; an explicit look can separately emit its event. |
| `net` | Socket/session state, cell membership, stream-local IDs and quantized replication baselines | Transform/model/flags, immutable manifests and only each manifest's declared replicated terms. Enqueues decoded inputs. No rules, economy, scene layout or direct gameplay writes. |
| `record` | Record IDs, append buffers and output files | Completed record values, not a world reference. Producers supply changed/result/cause and attribution. Creation records supply maker metadata; seed bootstrap is explicitly marked. |
| `snap` | Snapshot buffers/files; explicit table reconstruction before stepping | Section serializers receive each named table read-only. The executable assembles sections. Restore invokes the same structural helpers and rebuilds derived state; it does not reseed the scene or run authored top-level code. |
| `elaboration` | Requests, capture references and claim/answer state | An explicit capture selection and ordinary authorized inspect results. Fixture validation runs in another process. Only a successful fixture answer submits an ordinary registry edit; this module cannot patch arbitrary tables. |

Effective property lookup is a small data-only function over the exact columns and definition records required by the term's source. It must not grow into a general world API. Intrinsic values come from material definitions, measured values from bake output, state from handlers, and settings from the documented fallback order. Rules never receive the text table.

The contracts should expose these exact projections rather than a blanket `Objects&`. References to columns remain references across object allocation; do not retain a span into a vector that allocation may grow.

| Operation/view | Exact access |
|---|---|
| Identity lookup | Read `generation`, `model`, `material`, `flags`; no owner or text. |
| Spatial update | Write `position`, `rotation`; read geometry/model/flags and the relevant intent rows. Parent/built-in relation maintenance is a separate operation. |
| Authority lookup | Read `generation`, `owner`, `group`, `preset`, `plot`, player's groups, `grant_by_key` and grants; spend checks additionally access the one account and grant/parent counters. No text, physics or script state. |
| Own-state write | Write only the selected state/process columns for the invocation's self or declared parts; read term source/kind and part membership. No shared total or foreign state write path. |
| Contribution update | Write the selected term's `shared` and contributor's `gives_to`; read its combine definition and eligible subject handles; enqueue changed keys. No ledger, object owner or text. |
| Authored relation update | Write the named authored relation's `out` and `in`; validate handles. Built-in relation IDs are rejected here. |
| Action discovery | Read declarations and term input metadata; requested lists filter current body/source rights through the narrow authority function before pagination. Detailed help for any known action and fixed observation hints remain available. No rule execution or state writes. |
| Replication encode | Read generation/model/flags, position/rotation, manifest asset/parameter/replicated declarations and effective values for those declared IDs. No permission, treasury, school or oxygen view. |
| Attribution | Read maker/creation time for the explicit things and author/creation time for the executing script; receive inherited Origin. No causal-log traversal or gameplay mutation. |
| Capture/snapshot section | Read the explicitly selected section tables only. Capture selection comes from observed handles, spatial query results and relation neighbors, not unrestricted privileged inspection. |

All writes from script host calls go through the corresponding owner above. A script's implicit authority covers its own object and declared parts; arbitrary other objects require contributions, events or an ordinary permission-checked action. A request to execute an action is not a writable table reference.

## Permitted dependency graph

`store` has no dependency on other game modules. `react` depends on data types and tables, Luau and pure value helpers; its dispatch/contribution/watch tests link without Jolt, Detour, networking or a world executable. Queue, timer and Origin record types may live in shared data-only headers; they must not create a step/reaction link cycle. `space` links Jolt, Recast/Detour and the glTF reader. `perm` depends on table types and narrow lifecycle helpers. `net`, perception, record and snapshots consume their specified read views. The executable is the only composition root.

Thin script host bindings may link the runtime to individual space/permission/intent functions. Bind each native closure to its exact table references and invocation metadata. Do not introduce a shared host context containing every subsystem. Keep these adapters outside the engine-free reaction target. No virtual interfaces, service locator, transaction layer or plugin framework is needed.

The Python gateway depends on the public protocol and immutable asset metadata. Its state is limited to transport sessions, public responses and queued events; native observation compaction remains authoritative. Bake depends on build123d/OCCT, meshoptimizer and standalone native asset helpers; it submits completed results as world inputs. Measures depend only on records/adapters. Browser code depends on the wire/asset contracts. Agent policy is a separate owner-side program with no engine imports or privileged store access.

## Contract decisions from the restart review

1. **Host ABI omissions.** S4 does not specify the body-neutral primitive calls or how a body reads a held object's mass/hardness. Add narrow live `read(handle, term)` access for handles acquired through relations, delivered events or spatial queries, and explicit movement/attachment/holding/sound bindings. Add an own-transform/sweep primitive where needed for a closing door. The humanoid and door scripts select when and why to invoke them. None of these functions accepts an action name to interpret.
2. **Event provenance and targets.** Define an event envelope containing its term, typed value, sender/actor and acquired handles. Preserve that acquisition through delivery so generic authored interactions can reply without arbitrary remote writes. Keep primitive quantities numeric with declared terms/units; do not introduce natural-language action interpretation. Specify a sufficient event payload for the authored pour interaction before assigning it.
3. **Values visible to space and rendering.** Supply explicit term-ID bindings for generic visibility/light roles and manifest data for render roles. Space may calculate CPU illuminance and transparency from these values; scripts supply the values. Replication serializes the manifest's selected IDs without interpreting their meanings. Transforms convert Z-up server coordinates to the asset/client frame at one documented boundary.
4. **Player wallets and issuance.** Technicals §§13–14 and Specs S1.7 specify one balance per player. Objects and groups have no balances; income goes to the owner wallet. Scripts require explicit capped, expiring Spend grants on that wallet. Issuance is a separate architect-provisioned authority; its policy remains authored. Test denied implicit owner spending, shared delegated caps and restore without duplicate issuance.
5. **Seed and forage.** One data-driven start format supplies both modes and the stakes setting. Content installation uses normal bake/registry/script paths. Initial resources and identities are bootstrap facts, not per-step engine rules. The start format specifies how procedural placements reference one another without leaking numeric IDs into native modules.
6. **Latest reaction semantics.** Keep partial changes after handler error/cutoff, no trigger snapshots, strict re-check after each input, persistent queued watches, bounded logged event overflow and at least one background catch-up item per step. Only valuables swaps check all prerequisites before changing either side. No rollback, workflow planning or deterministic replay machinery.

The approved contracts must include public function signatures, exact read/write tables, allowed includes/links, input/output examples, units and one end-to-end interaction trace. Unresolved decisions above block the affected delegation, not unrelated work. Routine constants remain in one config file; no contract should add realism or guarantees beyond the game requirements.

## Original implementation sequencing recommendation

Approve narrow contracts first, then build the smallest real vertical slice: novel baked object, authored body action, authored material response, generic record and browser update. In parallel, implement the engine-free reaction library, spatial library, permissions, bake workers and protocol/client against those contracts. Add the café and institutions as authored workload packages only after the slice proves that content can be removed, replaced and composed. Reject a slice that passes its demonstration by bypassing the boundary: such code must be reworked before further content builds upon it.

## Review of implementation contract before delegation

Reviewed `architecture.md`, `content-contract.md`, `server/store/store.hpp`, `server/store/store.cpp` and `tests/store_test.cpp`. The separation is substantially improved. The contracts remain conditional on the following corrections before the affected runtime APIs are delegated; no implementation changes were made in this review.

1. **Make dispatch source and authority target distinct.** A body handler executes on the body, but its selected physical target is another object. Define declaration-driven routing and precedence for native player/place, body, held and target sources, including collisions. Never select a path by spelling a verb. A dispatcher sees declarations, identities and opaque callback bindings; it cannot inspect binding-local tables. Step exposes queued work, not a callback that captures the whole world. Negative test: register a new body action and a target handler with the same term and verify the documented routing without a native edit.

2. **Put script actions in the current drain.** Architecture currently says `self:act` enters the same input queue. That must not put a causal action behind the next already-arrived external input. Queue it as foreground work after the current handler returns and drain it before the next external input, subject to the existing budget/backlog rules. Return queued status rather than claiming an effect before execution. Preserve installed-script identity and Origin; do not re-enter a running coroutine. Test: input A causes a script action, and input B in the same step reads its result.

3. **Define VM state that snapshots can actually restore.** Binding-local native data is acceptable; a common pointer to all bindings' tables is not. A transient invocation may carry self, handler, Origin, direct-operation scope and deadline, but no subsystem registry. Mutable Lua globals, captured tables and writable upvalues cannot become a second authoritative state outside `self.state`. The root decision is cached immutable closures, readonly globals/captured tables and public AST validation rejecting upvalue writes. `self.state` is a tagged proxy for a flat authoritative map with string/integer keys and number/bool/string/handle values; writes are immediate and nil deletes. Scratch Lua tables remain ordinary tables. Test counter, random state, timer and cutoff behavior across restore, and deny retained initiating-actor authority.

4. **Write the value-resolution matrix into the signatures.** Intrinsic reads use material definitions; measured reads use the current asset, with mass computed from volume and current density; state/process reads use their columns and current world step; settings alone follow instance/model/plot/world precedence. Explicitly distinguish shared aggregate terms from writable state: `set`/`rate` must not overwrite a shared total. Define any state defaults separately rather than using one fallback for every source. Absence remains distinguishable from zero. Along-relation reads must rebind dependencies, thresholds and withdrawal when the relation changes or disappears. Tests use novel terms, current density changes and disappearing subjects.

5. **Scope direct body authority to an operation, not an actor ID.** The binding derives the checked actor/target/source scope from the actual direct invocation; Luau cannot supply or widen it. Specify the right for grasp, attach, impulse, release and both transfer endpoints. A held object is not automatically usable or debitable. Self movement/parts use the script's implicit own-object authority; foreign endpoints need their documented checked right. Timers/events use only installed-script grants. Check land entry throughout movement. Negative tests: an allowed target cannot authorize an unrelated impulse/debit; changing an argument cannot expand scope; delayed work cannot reuse a player's authority.

6. **Finish the conserved-transfer contract without a liquid kernel.** Accept the same declared numeric state term at both endpoints, reject intrinsic/measured/shared terms, settle processes at the current step, preflight both endpoint scopes, and then debit/credit together. Capacity, compatibility and spill stay in Luau; native transfer accepts quantities and returns the moved amount. The root decision is a local transfer guarantee, not global enforcement: the original own-state `set`/`rate` remain and authored laws may model sources/sinks. No new source/sink authority framework or rollback is required. Transfer is the documented narrow exception to foreign-state writes. Test denied/empty/partial transfers, handler cutoff immediately after transfer, and failed spill creation; all untouched remainder stays at its source.

7. **Keep financial authority on player wallets.** Use PlayerId-indexed balances and wallet scopes only. An object-handle read selects the current owner's wallet without granting Spend. Sale/gift revokes old installed-script financial grants. Listable capped issuance needs architect authority and cannot follow from installation, ownership or an institution's name. Test denial, cap preservation, sale/revocation and snapshot continuation.

8. **Meter actual allocations, not offered supply.** The content contract correctly requires interval delivery for authored procurement. Specify a piecewise-constant integral updated when allocation changes, with an explicit rule attributing served supply to suppliers, such as proportional shares. Persist its value/rate/step and the script's settlement cursor. No per-step polling or native procurement policy is needed. Test 100 W offered with 30 W demanded, demand falling to zero, two suppliers, and a mid-period allocation change: meters must represent delivered amounts rather than bill all offered power.

9. **Complete the authoritative snapshot inventory.** Shared geometry assets cannot hold per-submission model identity, author, text, selected material or installed behavior. These remain authoritative catalog rows. Include model-to-current-asset/script mappings, parameter blocks, script author/creation metadata, player-wallet balances, last-delivered watch values, process revisions, pending typed event payloads and allocation integrals in explicitly assigned S10 sections. Persist only scalar/handle invocation data, never native pointers or Lua closures. Restore must not reseed or rerun top-level side effects. Capture expansion is the specified one-hop relation neighborhood plus referenced metadata, not recursive traversal of a connected world. Test a shared asset submitted by two authors/materials and a pending cross-author chain across restore.

The base store is small and appropriately free of subsystem dependencies. Its randomized sparse-column test and stale-handle/vector-growth test exercise real invariants. The initial review found the following ownership gaps; the revised contract fixes plot access and masked-writer ownership, and adds lifecycle cleanup. Other checks remain acceptance requirements:

| Finding | Concrete correction and check |
|---|---|
| `AuthorityWrite` exposes mutable `plot`. | Remove it from permission writers. Plot membership follows placement/movement through a separate writer; a preset/grant/sale function cannot relocate an object into another jurisdiction. Keep only the authority columns an individual operation changes. |
| Runtime flags need enforced bit ownership. | Give space masked access to `Static`, `Dynamic`, `ScriptedMotion`, `Held`; asset completion gets only `Proxy`; permissions gets `NoCopy`, `Escrow`; `Body` remains lifecycle-only in this prototype. Review disposition: approve the direction, close these signatures and ownership rules, then delegate independent libraries. A successful demonstration without these boundaries is insufficient evidence of a modular monolith.

Follow-up: the revised root contract now closes routing, immediate action draining, source-specific reads, direct-operation scopes, local transfer semantics, flat state storage, account/issuance authority and the missing snapshot inventory. `record::Origin` is the shared causal type. The agreed record protocol buffers only each invocation's emitted work/timers/action requests and diagnostic drafts, then stamps them with the completed handler's Origin. For a direct action, its bounded envelope holds completed handler drafts until the final action record can be appended first. State changes remain live throughout; there is no transaction, rollback, descendant-chain wait or history traversal. The precise proposed step/react APIs and verified Luau hooks are in `react-api.md`.
